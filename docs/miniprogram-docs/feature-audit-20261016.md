## 二、建议新增的功能（按优先级）

### P0 — 涉及合规或「没有它就有人被骚扰」

> ✅ 本节三项**全部已落地**（2026-10-16 这轮）。

- [x] **账号注销 / 删除我的数据**。我的页 →「账号与数据」→ 注销，7 天冷静期且期内可撤销  
  （云函数 `accountCancel` / `accountCancelUndo` / `accountPurge`，`account_reqs` 集合）。
  **拍板结果（第 5 节问题 5）**：帖子/评论走**匿名化保留**而不是一并删除 ——
  孤儿内容比"历史讨论突然断掉一截"更可接受。资料、拉黑、私信、收藏、备忘是真的删。
- [x] **社交场景的举报入口**。`utils/report-person.js` 统一收口，落点在**私信页与名片页**两处，
  服务端会把最近 10 条私信做成证据快照随举报一起存。**拍板结果**：举报人**永不自动封号**
  （一个人说了算的封禁太容易被滥用），一律进队列由审核员处置。
- [x] **陌生人消息请求箱**。**拍板结果（第 5 节问题 4）**：进请求箱。
  `chatList` 回执拆成 `requests`（还不是好友 + 我从未回过 + 不是我删掉的）与 `list` 两段，
  只有我主动点「接受」才进主列表。

### P1 — 明显影响日常使用的缺口

> ✅ 本节五项**全部已落地**。

- [x] **好友申请撤销 + 「我发出的申请」列表**。`friends.wxml` 已有「我发出 N 条申请」分段，
  每条可撤销（`friendCancel`，删掉那条 pending 记录并清掉冷却）。
- [x] **好友备注名**。`alias` 字段只影响我这一侧；名单行显示备注名 + 小字「原名：xxx」，
  私信标题也优先用备注名。
- [x] **私信消息操作**：长按一条消息 → 复制 / 撤回（2 分钟内，与服务端 `RECALL_MS` 同值）/
  重发 / 举报；会话列表长按 → 删除会话（只删我这一侧，对方那份保留）。
- [x] **站内通知中心**。`notifications` 集合 + `notifyList`/`notifyRead` + 「消息」页。
  谁回复了我的帖子、谁申请加我、谁解除了关系都进这里，订阅消息断了靠它兜底。
- [x] **关于页**（版本号 + `BUILD`/`FEATURES` + 免责声明 + 联系方式）。
  版本号不一致时会明确提示「云端云函数是旧版」。

### P2 — 体验加分项

- [x] **跨模块统一搜索**。`sub/search/search.*`：课程 / 帖子 / 闲置 / 校园活动四路一起搜，
  结果**分组**展示，复用 `utils/search.js` 内核（不是另写一套匹配规则）。
  ⚠️ 同学**没有**并进来 —— 同学名单走实名，混进内容搜索结果里会有"被人搜到"的观感，
  要加得单独评估。
- [x] **收藏招聘会**（原建议是「加进校历 / 提醒」，已改）。就业网同步来的场次已经有 `jobTs` / `jobEndTs`。
  评审时否掉了「加进校历」：校历在这个项目里是教务处级别的学期节点，往里塞一场宣讲会，
  会把节点列表污染成信息流，「校历」这个入口就不再回答「这学期什么时候开学」了。
  改成收藏：只给招聘会这一类开入口（官网公告是看完就走，不收），卡片上放星标，
  活动详情页也有。收藏时把时间、地点存成快照 —— 官网活动只在窗口内
  （招聘会按举办日期、公告按发布时间），出了窗口列表里就没有这条了，
  但「我的收藏」里仍然看得见是哪一场、在哪办，只是标「已不在列表」。
- [x] **帖子编辑**（发完可改、改后重新过审）。`sub/forum/edit/*` 一套页面兼发布与编辑，
  云函数 `postEdit` **改完重新过一遍内容安全**（不然改一改就能绕开审核），赞和评论都在。
- [x] **图片长按菜单统一**：保存 / 转发 / 举报。**这条拆开看，三项结论不一样**：
  - **保存** —— 已经能用了。`show-menu-by-longpress` 是微信原生菜单，长按就能存，
    零隐私成本。自己接管长按去重造一个，就得申请 `scope.writePhotosAlbum` +
    隐私指引新增「相册」一项，为「统一菜单」多要一份权限是净负收益，不做。
  - **转发** —— 做不到。小程序没有任何 API 能在任意位置主动唤出转发面板，
    只有 `button open-type="share"` 和右上角菜单两条路。不是偷懒，是平台没有。
  - **举报** —— 这条有价值，但**问题不在长按菜单，在审核员看不见图**。
    真实的坑是：广告常常长在图里（二维码、微信号截图），正文只有「加我」两个字，
    而审核队列 `getQueue` 以前只给正文前 160 字 —— 审核员看不到图，只能凭感觉判。
    已改成**内容类举报把配图一起带回队列**（截 3 张）。
    顺手修了一个既有 bug：那个证据区是 `src="{{src}}"` 直接渲染图片的，只能吃 URL，
    而举报「人」的快照是对象数组（`{from,text,time}`）也挂在 `evidence` 上，
    导致名片举报那一栏一直是一块加载不出来的碎图 —— 现已改名为 `personEvidence`，
    文本证据走 `desc`，不进图片区。
- [x] **深色模式**：全站令牌化 + 跟随系统（`app.wxss` 定义 29 个 `--c-*` 令牌，
  `@media (prefers-color-scheme: dark)` 只重定义令牌值；`theme.json` + `app.json` 的
  `darkmode` 管导航栏与 tabBar）。深色不是把颜色取反 —— 纯黑配纯白看久了累，
  底色走 `#0d1117`、卡片 `#161b22`、彩色整体提亮一档。由 `tools/tokenize-colors.py`
  批量替换约 1107 处写死色值，`scripts/check-theme.cjs` 守卫「light/dark 令牌集必须完全一致」。
- [x] **列表分页补齐**：抽出 `utils/pager.js` 统一分页状态机（`reset` / `keep` / `more` / `all`），
  校园活动（同学发起块）、学习资料、我的帖子、同学名单四页都接上了。
  `.load-more` 提到 `app.wxss` 全局，四页样式一致。
  ⚠️ 分页一上就暴露两个真实缺陷（已修、并由 `scripts/test-pager.cjs` 钉住）：
  ①「我的帖子」清空全部原来拿的是 `data.posts`，分页后那只是**已显示的切片**，
  会只删掉屏幕上那几条却提示「已清空」；②「共 N 条」「找到 N 位」原来绑在切片长度上，
  会**随着往下滚越变越大**。

## 三、建议完善的功能（现有功能的缺口）

### 3.1 社交

> ✅ 本节六项**全部已落地**。

- [x] **解除好友留下痕迹**。`removeFriend` 给双方会话各推一条系统消息（「你们已解除同学关系」），
  居中渲染成小字说明而不是气泡 —— 气泡意味着「有人说了这句话」，会让人以为是对面发的。
- [x] **解除好友后私信历史的提示**。会话页顶部挂关系状态条：还不是好友时**提前**把
  「还剩几条」说清楚。配合上面那条系统消息，用户才知道「关系变了」而不是「私信坏了」。
  **拍板结果**：聊天记录**保留**（刻意的）—— 突然清空一段对话比留着更吓人。
- [x] **好友名单批量查 + 分页**。`listFriends` 改成 `where(_id in [...])` 分片批量取
  （单次 `in` 上限 100），并支持 `offset`/`limit`。
  以前是 `for` + `doc(id).get()` 逐个查 —— 50 个好友就是 50 次网络往返，
  在云函数默认超时下必然 timeout，表现为「同学列表转圈然后空白」。
- [x] **拉黑与解除好友的交接**。取了建议里的**后一种**（标出来，而不是多问一句）：
  同学名单行上标 `已拉黑`，另有独立的「黑名单」页签。
  **为什么不做「要不要顺便解除好友」**：拉黑已经是明确动作，后面再追一句确认，
  等于把一次决定拆成两次；而且解除好友是可逆的（重新加即可），标出来就够判断了。
- [x] **非好友配额的数字收敛**。`utils/friend.js` 导出 `STRANGER_QUOTA`，名片页文案统一读它，
  会话页显示服务端回执。**改数字只需改云函数与 `friend.js` 两处**（已写进 `ONBOARDING.md`）。
  ⚠️ 前端那份**只用于文案**，权威闸门始终在云端 —— 改前端不会真的放开额度。
- [x] **「看自己的名片」的死分支**。取了建议里的**前一种**：`getProfile` 对自己的 openid
  返回**本人完整资料**（自己的数据本来就不敏感），名片页那块 `isMe` UI 现在走得到了。
  「留着一块永远不显示的 UI 比没有它更容易误导后来的人」这句话是这条建议最值钱的部分。

### 3.2 私信与消息

> ✅ 本节三项**全部已落地**。

- [x] **会话列表分页**。`chatList` 支持 `offset`/`limit`，前端接 `onReachBottom` + `hasMore`。
  ⚠️ 云侧**不能**直接 `skip/limit`：被过滤掉的会话会让每一页都变短，用户以为到底了，
  实现上是多取一批再本地切片。
- [x] **私信轮询**。取了建议区间的**上沿 20 秒**（`POLL_MS = 20000`）：15 秒太勤，
  挂在聊天页十分钟就是 40 次云函数调用。另有一条：用户点进名片页时聊天页只是被盖住、
  并没有销毁，那时**停掉**轮询，纯属白烧调用。
- [x] **图片内容安全**。取了建议里的**补上调用**（不是删注释）。
  用的是 `cloud.openapi.security.mediaCheckAsync` 而**不是**同步 `imgSecCheck`：
  同步接口有 1MB / 1 秒的硬限制，一张手机照片就够超时；
  异步只提交 URL 就返回 `traceId`，结果由微信侧回推到 `user` 云函数的消息推送回调。
  另有 10 分钟兜底扫描：结果一直回不来就标 `unverified` 而不是无限期挂在 `pending`。
  ⚠️ 这类注释与实现不一致的问题，本轮已由 `scripts/` 下的检查脚本持续盯（见 1.6）。

### 3.3 内容与审核

- [x] **`listRequests` 的静默失败**。回执加 `degraded` 字段：查询真的失败时不再伪装成
  「没有申请」，页面据此提示「刷新失败，下拉重试」。
  **这条的价值在区分两种"空"**：「确实没有新申请」和「没拉到」必须能分开，
  混在一起就是历史上「申请收不到」的形态。
- [x] **审核员操作日志**。`mod_logs` 集合：封号 / 删内容 / 置顶都留一条（action + 目标 + 人 + 时间）。
- [x] **屏蔽词表可配**。代码里那份是**兜底**，审核员在审核页填的那份**叠加**上去（5 分钟缓存）。
  ⚠️ 是「叠加」不是「覆盖」：写覆盖的话，审核员清空输入框就等于关掉整个词表。

> 📋 **索引三项属于控制台手动操作**，代码侧已按「查询形态」写好，清单可照抄在
> `docs/DATABASE.md`（`contacts(toOpenid,status)`、`chatList` 的 `(a,updatedAt)`/
> `(b,updatedAt)`、`users.banned`）。**不建也能跑**，只是数据量上来后会全表扫；

## 四、故意不做（有明确理由，不是遗漏）

| 事项                                       | 为什么不做                                                     |
| ---------------------------------------- | --------------------------------------------------------- |
| 在线支付 / 担保交易                              | 个人主体资质做不到；帮助页已如实写明                                        |
| WebSocket 实时私信                           | 要单独的消息服务与断线重连，校园场景「晚一分钟看到」完全够用                            |
| 抓公众号图文                                   | 没有可用的列表接口，标题里也没有结构化时间字段（错日期比不显示更糟）。见 `ARCHITECTURE.md` §8 |
| 抓招聘公告 / 岗位栏目                             | 是公告不是活动（没有时间地点）；岗位量级上千，该去就业网投简历                           |
| 建「加好友」独立页面/独立按钮                          | 本轮需求明确要求整合进现有页面与流程（已落进名片页、搜索结果、私信锁块）                      |
| 给 `block`/`unblock`/`removeFriend` 加封禁拦截 | 被封的人也该能把自己从别人那儿摘出去                                        |
| 自造图片长按菜单的「保存」                               | `show-menu-by-longpress` 原生就有，零隐私成本。自己接管长按要申请 `scope.writePhotosAlbum` + 隐私指引新增「相册」一项 —— 为菜单统一多要一份权限是净负收益 |
| 自造图片长按菜单的「转发」                               | 小程序没有任何 API 能在任意位置主动唤出转发面板，只有 `button open-type="share"` 和右上角菜单 |
| 招聘会「加进校历 / 提醒」                             | 校历是教务处级别的学期节点，往里塞一场宣讲会会把节点列表污染成信息流，「校历」就不再回答「这学期什么时候开学」了。改成**收藏招聘会** |

## 五、需要你拍板的问题

1. **好友配额是否要「按天重置」？** 当前不重置（一次给足、用完为止），因为按天重置等于  
   「每天 3 条」的永久骚扰通道。要不要给个例外，比如「对方已读但没回」也算一次机会？

   这类真实需求也不友好。要不要禁掉图片、只留文字？
3. **解除好友前是否要提示「对方也会看不到联系方式」的双方影响？** 现在只讲了我这一侧的后果。
4. **陌生人消息是否进「消息请求箱」**（见 P0 第 3 条），还是维持现在直接进主列表？
