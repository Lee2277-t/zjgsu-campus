# UI 优化设计计划

> 制定日期：2026-10-17 ｜ 状态：**待审阅**（确认后才动代码）
> 口径：全部结论来自对 `pages/`（40 页）、`components/`（12 个组件）、`app.wxss`（535 行）的实际扫描，
> 数据均可复算（附在各条后面的括号里）。
> 原则：**不重做，只收口**。现有设计系统方向是对的，问题在执行层的漂移。

---

## 1. 先说结论：这个项目的 UI 底子是好的

审阅前先对齐一个事实——这次优化**不是推翻重做**。以下几项已经是正确状态，计划里明确不动：

| 已有的好底子 | 证据 |
|---|---|
| 完整的 `--c-*` 色彩令牌 + 深色模式 | `app.wxss` 29 个令牌，深浅两套，`check-theme.cjs` 14 项校验 |
| 场景色制度（论坛紫/闲置橙/校园绿/资料青） | 令牌 + `.scene-*` / `.tag--*` 语义类 |
| 设计决策有注释记录 | mine / campus / detail 等页的 wxml 头注释写明「为什么这么做」 |
| 按压反馈、热区 ≥88rpx 的规范 | `.tap` / `.pressable` / `.hit` 在 app.wxss 已定义 |
| 空状态文案按成因区分 | 课程页空状态有 4 种文案，不是一句「暂无数据」 |
| app-header 组件覆盖 34/40 页 | 头部已经收口 |

所以这次计划的主线是**「收口」**：把散落在 40 个页面里的私有数值收进令牌，把手写组件收进组件库。

## 2. 问题分析（每条都带实测数据）

### P1-1 字号漂移：15 个不同字号，规范只认了 4 个

`app.wxss` 文件头声明的字号是 36/28/24/20-22 四档，但实测全站有 **15 个不同字号**：

```
24rpx×153   22rpx×135   26rpx×106   28rpx×89    30rpx×51   ← 这几档合理
25rpx×12    27rpx×5     21rpx×3     23rpx×4     ← 非标值，肉眼难察觉但破坏字阶
34rpx×5     38rpx×3     32rpx×12    56rpx×6     ← 标题层漂移
```

非标值集中在 9 个文件（moderation / campus/add / blindbox / market/detail / search / about / account / guide / notify）。
**危害**：25rpx 和 24rpx 并排出现时，同一层级的文字「看起来差不多但说不清哪不对」——这正是界面显廉价的头号原因。

### P1-2 间距不在栅格上：18/14/10 这些「手抖值」

实测 padding 出现 18rpx（7 处）、margin-bottom 出现 14rpx（5 处）、18rpx（4 处）、10rpx（4 处）。
**危害**：卡片间距 24 和 18 混用，滚动时列表节奏忽松忽紧。

### P1-3 圆角漂移：标准 32/24/999 之外还有 7 种

实测非标圆角：28rpx×4、40rpx×3、44rpx×1、38rpx×1、12rpx×3、8rpx×5、4rpx×1。
卡片 32、内层 24、胶囊 999 的三层体系已经建立，但总有新写的元素随手取了 28 或 40。

### P1-4 字重双轨：600 和 700 混用无规则

`font-weight:600` 出现 175 次，`700` 出现 34 次。没有约定什么场景用哪个——标题有的地方 600 有的地方 700。

### P1-5 写死色值残留 127 处，审核页是重灾区

| 文件 | 写死色值数 |
|---|---|
| `admin/moderation/moderation.wxss` | **26** |
| campus/blindbox | 10（固定深色页，**刻意保留**） |
| forum/detail | 9 |
| forum/hole | 8（固定深色页，**刻意保留**） |
| forum/list、mine、forum/post、course/review | 5-8 |

树洞/盲盒是固定深色主题页，写死色是设计决策，不动；**真正要收的是 moderation 的 26 处和常规页的残留**——这些在深色模式下不会变，是上一轮令牌化漏网的。

### P1-6 组件收口不足：建了组件库，但一半页面还在手写

| 组件 | 使用页数 | 问题 |
|---|---|---|
| app-header | 34 | ✅ 已收口 |
| base-button | 14 | ✅ 尚可 |
| empty-state | 12 | ⚠️ 另有 8+ 页手写 `.empty` |
| **base-card** | **2** | ❌ 40 页的卡片都直接用 `.card` 类，组件形同虚设 |
| bottom-sheet | 2 | ❌ 至少 5 处手写 `.sheet` 抽屉 |
| pill-selector | 2 | ❌ 分段控件各页手写 |
| vote-card | 1 | ❌ 仅详情页一处 |

页面私有样式体量佐证：campus.wxss **622 行**、forum/detail **579 行**、post 505 行、moderation 500 行——这些行数里有一大半是在重复发明 `.card` / `.sheet` / `.chip` 已有的东西。

### P1-7 tabBar 用 PNG，图标 189 个 SVG 有多色冗余

- tabBar 10 个 PNG：高分屏发虚，且无法随深色模式变色（深色下只能靠 `tabBgColor` 衬托）。
- 图标命名 `name--color.svg` 是规范的，但同一个图标有多色变体（如 `book-open` 有 brand/campus/faint/market/muted/profile **6 份**）——SVG 不能像字体那样 `color` 换色，只能整份复制。

### P1-8 骨架屏覆盖不全

论坛列表、闲置列表有骨架屏（`.sk-card`）；**课程列表没有**——首次进课评页是白屏跳到内容，和相邻 tab 的体验不一致。

### P1-9 按压反馈两套并行

mine 页用 `hover-class="mn-stat--hover"`（原生属性），其他页用 `.tap:active`（CSS）。两套机制视觉效果不同（hover-class 是整卡换底，:active 是缩放+透明），用户在「我的」和「论坛」点卡片的手感不一样。

## 3. 整体视觉风格方向

### 3.1 配色：**不动色板，只收口**

现有色板（主蓝 #2B5AED + 四个场景色）辨识度和一致性都好，改动它等于换品牌，不做。
做的事只有两件：

1. 把 P1-5 的写死色值逐个换成令牌（特殊固定深色页除外）；
2. 新增**阴影令牌**——现在 `box-shadow` 的 rgba 值各页手写，统一为三档：
   - `--sh-1` 卡片：`0 8rpx 24rpx var(--c-shadow)`（现有，不变）
   - `--sh-2` 浮层/抽屉：稍深
   - `--sh-3` FAB/吸顶：最强

### 3.2 字体：字阶从 15 档收敛到 8 档，全部令牌化

新增 `--fs-*` 令牌（rpx）：

| 令牌 | 值 | 用途 | 现状对应 |
|---|---|---|---|
| `--fs-hero` | 56 | 大数字（统计卡、倒计时） | 56rpx×6 保留 |
| `--fs-title` | 36 | 页标题 | 36rpx 保留 |
| `--fs-h2` | 30 | 卡片标题 / 区块头 | 30rpx 保留 |
| `--fs-body` | 28 | 正文 | 28rpx 保留 |
| `--fs-sub` | 26 | 次正文 / 列表副行 | 26rpx 保留 |
| `--fs-aux` | 24 | 辅助说明 | 24rpx 保留 |
| `--fs-tag` | 22 | 标签 / 胶囊 | 22rpx 保留 |
| `--fs-micro` | 20 | 角标 / 版权声明 | 20rpx 保留 |

**收敛规则**（这就是审阅要点）：25→24、27→26、21→22、23→22、34→36、38→36、32→30。
全部是 ±2rpx 的归并，视觉上几乎不可感知，但字阶从此是干净的等差。

**字重规则**（解决 P1-4）：
- 400 正文；600 一切强调（标题、按钮、数字）；**700 只给 hero 大数字和页主标题**。
- 执行：34 处 700 逐个核对，非 hero/页标题的降为 600。

### 3.3 间距：8rpx 基准栅格

新增 `--sp-*` 令牌：`--sp-1:4 / --sp-2:8 / --sp-3:12 / --sp-4:16 / --sp-5:20 / --sp-6:24 / --sp-8:32 / --sp-10:40`。

**收敛规则**：18→16 或 20（按上下文）、14→12 或 16、10→8 或 12。
卡片外距统一 24（现状主流），卡片内距统一 28（现状 `.card` 已定）。

### 3.4 圆角：四层 + 胶囊

新增 `--r-*` 令牌：`--r-s:8 / --r-m:16 / --r-l:24 / --r-xl:32 / --r-pill:999`。
**收敛规则**：28→24 或 32、40→32、44/38→32、4/8→8、12→16 或 8。

### 3.5 动效规范（新补，现在没有成文约定）

- 页面入场：只用 opacity（现有 `pageIn` 0.28s，**不动 transform**——这是硬约束）；
- 按压：`:active` 缩放 0.985 + 透明度 0.72（现有，统一推广）；
- 抽屉/弹层：0.26s `cubic-bezier(0.2,0.8,0.2,1)`（现有 `.sheet`，作为标准）；
- **不做**：弹性过冲动画（overshoot）——小程序渲染层做不稳，容易掉帧。

## 4. 各页面布局与组件优化方案

> 按「用户打开频率 × 问题严重度」排序。每页给出：现状 → 改法 → 预计工作量（S=半小时内 / M=半天 / L=一天）。

### 4.1 课程列表（tab1，入口页）—— M

- **现状**：吸顶筛选 5 层（分段→搜索→学院→类型→排序），信息密度高；**无骨架屏**；空状态 4 种文案已好。
- 改法：
  1. 补骨架屏（对齐论坛列表的 `.sk-card` 模式）；
  2. 吸顶区 5 层压缩为 4 层：「学院」和「类型」两排 chip 合并为一排（类型chip前加色点区分），减少首屏占位约 88rpx；
  3. 「给老师单独写评价」入口卡（`ls-tch-add`）只在老师档出现，位置合理，不动；
  4. 数值令牌化（该页有 5 处写死色值）。

### 4.2 论坛列表（tab2）—— M

- **现状**：搜索+话题+板块+树洞入口+盲盒入口+排序 6 个模块堆在首屏，首屏信息过载；骨架屏已有。
- 改法：
  1. **树洞入口和盲盒入口合并为一行双卡**（现在各占一行整卡，垂直空间浪费）；
  2. 排序分段控件 6 个选项（最新/置顶/热门/赞/踩/留言）压为横向滚动，避免两排折行；
  3. 「有 N 条内容被暂停展示」入口（`muted-entry`）视觉上降为次级（现在是橙色整卡，抢了主内容风头）；
  4. 帖子卡片入场动画已有 stagger（`animation-delay`），保留。

### 4.3 闲置列表（tab3）—— S

- **现状**：结构清晰（搜索+分类+两个入口+列表），空状态有插画（`empty-market-bag`），是好的示范。
- 改法：仅数值令牌化 + pill-selector 已是组件，**改动最小的一页**，作为组件化的验收样板。

### 4.4 校园页（tab4）—— L（最重的一页）

- **现状**：622 行私有样式，三档切换（活动/校历/地点），招聘会收藏刚上线。
- 改法：
  1. **拆分优先级最高**：把活动卡片（`.ev__*` 系列）抽成 `components/campus/event-card` 组件——现在官网活动卡和同学活动卡是两套手写结构，80% 样式重复；
  2. 三档切换器（hub-filt）视觉上对齐 app.wxss 的 `.segmented` 标准；
  3. 「官网同步条」和「招聘会收口条」的样式各写了一份相似的，合并；
  4. 数值令牌化（6 处写死色值）。

### 4.5 我的（tab5）—— S

- **现状**：结构干净、决策注释完整，是全站写得最好的一页。
- 改法：
  1. **按压反馈从 hover-class 换轨到 `.pressable`**（解决 P1-9 双轨制，这页是 hover-class 用得最多的）；
  2. 顶部渐变 hero 区的渐变色值写死（`mn-hero`），换成 brand 令牌派生；
  3. 其余不动。

### 4.6 论坛详情（高频页）—— M

- **现状**：579 行样式；作者行、投票卡、三连、评论气泡、固定底栏都有，功能密。
- 改法：
  1. 评论气泡的 1/2/3 图网格（三套写法）抽成 `components/ui/image-grid`——发帖页、私信页也有同款九宫格逻辑，三处合一；
  2. 固定底栏输入区与 chat 页的输入栏对齐（两页各自手写，高度差 8rpx）；
  3. 树洞深色变体（`detail-page--hole`）保留写死色（刻意）。

### 4.7 私信会话（chat）—— M

- 484 行样式。聊天气泡、图片消息、关系状态条都私有。
- 改法：气泡抽 `components/chat/bubble`；输入栏与论坛详情共用（同 4.6-2）。

### 4.8 审核页（admin/moderation）—— M

- **写死色值 26 处，全站最大户**；500 行样式。
- 改法：令牌化优先（这页是深色模式下破损风险最高的）；审核卡片抽组件；证据区（刚修过 `personEvidence`）样式并入卡片组件。

### 4.9 其余页面（批量处理）—— S

- course/detail、course/review、market/detail、search、friends、notify、account、about、guide、memo、places、resources、calendar 等 20+ 页：**只做数值令牌化 + 空状态统一**，不动布局。
- 空状态统一：全部走 `empty-state` 组件（现 12 页），其余 8+ 页手写 `.empty` 迁入；插画规范：只有「列表为空且有引导价值」的页配插画（market 已是样板），纯结果为空用文字即可。

### 4.10 明确不动的页面

- **树洞（hole）/ 盲盒（blindbox）**：固定深色主题，写死色是设计决策；
- **guide（应用说明）**：引导页风格独立；
- **campus/blindbox 的 488 行**：风格自成一体，只做数值检查不动结构。

## 5. 交互细节改进建议

| # | 改进点 | 现状 | 改法 |

| 1 | 按压反馈统一 | hover-class 与 .tap:active 双轨 | 全站统一 `.pressable`；hover-class 只留给需要自定义底色的极少数场景 |

## 6. 分阶段实施步骤

> 每个阶段独立可交付、独立可回滚；每个阶段结束都跑 `npm run check`（23 个脚本）+ 真机预览。

### 阶段 0：令牌扩展（零视觉变化，半天）
1. `app.wxss` 新增 `--fs-*`（8 个）、`--sp-*`（8 个）、`--r-*`（5 个）、`--sh-*`（3 个）令牌，**只定义，不替换**；
2. 深色模式媒体查询同步定义（中性令牌不变，所以多数只在 light 定义一次即可）；
3. `check-theme.cjs` 扩展校验：新令牌同样纳入「无悬空引用/无死令牌」检查。
- **验收**：`npm run check` 全绿；界面零变化。

### 阶段 1：数值收口（低风险，1-2 天）
1. 写 `tools/normalize-scales.py`（仿照 tokenize-colors.py 的思路）：按映射表把 25→24、27→26、18→16 等非标值替换为令牌引用，支持 `--dry-run` / `--report`；
2. 先跑 `--report` 出清单，人工核对每一处的上下文（比如 25rpx 是不是有意比 24 大一点）；
3. 分批替换、分批跑检查。**moderation.wxss 的 26 处写死色值**在这一阶段一并收掉；
4. 字重核对：34 处 700 逐个人工确认（脚本只列清单不自动改，字重是语义不是数值）。
- **验收**：`--report` 残留为 0；真机逐页截图对比（允许 ±2rpx 的细微差异）。

### 阶段 2：组件收口（中风险，2-3 天）
1. `image-grid`（详情/发帖/私信三处合一）；
2. `event-card`（campus 页两套活动卡合一）；
3. `chat-bubble`（chat 页）；
4. 输入栏组件（detail + chat 共用）；
5. `bottom-sheet` 推广到 5 处手写抽屉；`empty-state` 推广到剩余 8 页。
- 每抽一个组件，源页面样式应净减少——以 campus.wxss 从 622 行降到 <400 行为目标。
- **验收**：组件 props 有行为测试（沿用 test-*.cjs 模式）；页面 wxml 结构不变（标签换了，层级不换）。

### 阶段 3：视觉精修（中风险，2 天）
1. 论坛列表首屏瘦身（4.2）；校园页筛选器对齐（4.4）；mine 页按压换轨（4.5）；
2. 骨架屏补齐（课程/招聘会/通知）；
3. 阴影三档替换全站手写 box-shadow。
- **验收**：五个 tab 页首屏截图前后对比，给评审过目。

### 阶段 4：交互细节（低风险，1 天）
- 第 5 节的 3/4/5/6/8/10 项。每项独立 commit。
- **验收**：触感反馈在真机上逐个动作过一遍；懒加载用开发者工具「性能」面板看首屏请求数。

### 阶段 5：守护与文档（半天）
1. `scripts/check-ui-scales.cjs`：把字号/间距/圆角/字重的合法值写进检查，CI 化（并入 check-all.cjs）；
2. `README.md` 设计规范一节更新为新令牌表；
3. `docs/ONBOARDING.md` 补一条：「新写样式三问——字号用令牌了吗？间距在栅格上吗？圆角是四层之一吗？」

## 7. 验收标准（总）

| 维度 | 指标 |
|---|---|

### 10.3 过程中新发现并修掉的真问题

这三个都不在原计划里，是动手后才看见的：

1. **`rgba()` 写死色值 236 处，`tokenize-colors.py` 只扫 hex 所以一直没报**。
   其中 3 处近白遮罩（`rgba(255,255,255,.94)`）是真 bug：深色模式下它们是白底，
   而上面的文字跟着 `--c-muted` 变浅 —— **浅底浅字，直接看不见**。
   已修：`sticky-filter`（全局吸顶筛选条，最严重）、发帖页底部按钮条；
   地图浮层改用 `--c-over`/`--c-over-text`（深浅同值的一对，因为它压在永远浅色的地图上）。
   树洞 / 盲盒那 21 处 `rgba(255,255,255,*)` **刻意保留**——它们本来就是深色设计。

2. **热区 `92rpx`**：既不是标准 88 也不是大号 96，纯属当时手边写了个数。3 处已归位 88。

3. **按压反馈 6 种透明度**（0.6/0.7/0.72/0.78/0.86/0.88）：同一个 App 里点下去六种深浅。
   其中 0.7 和 0.78 与 0.72 的差不到 3% 亮度，肉眼分辨不出 —— 合并。
   0.6（删除类）和 0.86/0.88（大块元素）**保留**，它们有语义。
   顺带把 `hover { background: #f7f9fc }` 这种写死色值换成 `--c-sunken`。

**④ tabBar 图标：几何归一化（不是重画）**

先更正 §9 里的一个判断：**theme.json 覆盖不了 tabBar 图标**。
它只支持 `tabFontColor` / `tabSelectedColor` / `tabBgColor` / `tabBorderStyle` 这类颜色，
`iconPath` 只认 `app.json` 里那一份。项目其实早就接好深色模式了
（`darkmode: true` + `themeLocation: "theme.json"`，三个 tabBar 颜色都写成 `@tabFontColor` 这类变量），
所以「再出一套深色图标」没有意义 —— 微信不会去读。

真正的问题只有几何：`assets/tabbar` 里 10 个 PNG 都是 81×81（3x 标准），但墨迹大小和位置各不相同：

| 图标 | 改前墨迹 | 改后 |
|---|---|---|
| campus | 65×63，重心 y=46.2（偏下 5.7px） | 63×61，居中 |
| course | 61×60 | 61×60（本来就正） |
| forum | 62×62，重心偏上 3.2px | 63×63，居中 |
| market | 62×56 | 62×56（本来就正） |
| mine | **55×58**（最小，比 campus 小 10px） | 59×63 |

做法用脚本而不是手改：`scripts/normalize-tabbar-icons.py` 按 alpha 包围盒等比缩放到 62px 画心、
把包围盒中心挪到画布中心，缩走**预乘 alpha + 双线性**（否则边缘会混进透明像素的颜色发黑）。
默认是检查模式，`--fix` 才写文件，缩放比在 1±0.02 内直接跳过 —— 反复跑不会越磨越糊。

已加进 `npm run check` 的 python 组，以后换图标会被自动拦住。
