# 广告接入方案（预留与位置规划）

> 写这份文档的目的只有一个：**现在不用写广告代码，但有些决定一旦定错，将来改不回来。**
> 位置占了首屏就退不回去；底部 fixed 元素一多就打架。先把约束写死，将来接广告是加一个组件的事。

---

## 1. 先选路：两条完全不同的生意

| | 官方流量主（微信广告组件） | 自营商家直投 |
|---|---|---|
| 谁付钱 | 微信广告平台，按曝光结算 | 校园周边商家，按月/按位 |
| 门槛 | 小程序已上线、累计 UV 达标、无严重违规 | 你自己去谈，没有技术门槛 |
| 资格 | 需完成主体认证；个人主体也可申请（历史门槛 UV 1000，近期官方社区答复为 500，**以 mp 后台「流量主」页实际显示为准**） | 无 |
| 素材 | 平台投放，你控制不了内容 | 你审，能保证不出现网贷 / 学科培训 |
| 收益量级 | 低，见 §4 | 高 3–10 倍，但要卖 |
| 我的建议 | 只做 §2 第一梯队，当基线收入 | **主力**，尤其「闲置」和「考研/考证」板块 |

两条可以同时跑，但**不能同页叠放**：官方 banner 和你自己的商家卡叠在一起，用户分不清谁是谁，
平台也会判「干扰展示」。

---

## 2. 位置清单

优先级从高到低。所有位置都必须带「广告」二字标注，且不能做成按钮形状。

| # | 位置 | 形式 | 为什么可以放这儿 |
|---|---|---|---|
| 1 | 帖子详情页 **内容流末尾**（评论列表之下） | banner 或商家卡 | 用户已经读完正文，此刻是「下一步看什么」的空档 |
| 2 | 论坛信息流 **第 5 条之后**，只插 1 条 | 原生卡，与帖子卡同规格（`--r-*`、`--sh-*` 复用） | 首次曝光发生在用户已投入 5 条阅读成本之后，跳出率最低 |
| 3 | 「我的」下的二级页底部（收藏 / 草稿 / 我的帖子） | banner | 低频页，且用户目的已完成 |
| 4 | 搜索无结果页 | 商家卡 | 本来就什么都没找到，补位不算打断 |
| 5 | 闲置列表第 3 条后 | 原生卡 | 二手场景与本地商家天然相关（打印店、搬家、维修） |
| 6 | 抢盲盒 / 树洞次数用完后 | 激励视频换 1 次 | 用户主动换取，接受度最高，eCPM 也最高 |

**不要放**：聊天页、评论区两条留言之间、启动开屏、课程评价打分页。
前两个是对话/判断场景，插一条就断；后两个审核最严、流失最快。

## 3. 现在就存在的三个约束（这才是「需要预留的地方」）

### 3.1 详情页底部已经被 `input-bar` 占了

`sub/forum/detail/detail.wxml` 的评论输入栏是 `position: fixed` 贴底的。
banner 如果也做成 fixed，两者会叠在一起，输入框被挡。
→ **详情页的广告只能放内容流末尾**，不能 fixed。这条现在就定下来，将来不会返工。

### 3.2 列表数据来自远端同步，广告不能进缓存

`utils/store-sync.js` 会按 `posts.at` 分页拉取并**整份覆盖**本地 `posts`。
如果把广告项混进 store 的 `posts` 数组，下一次同步就被冲掉，还可能在断网时被当成真帖子渲染出来。
→ 广告必须在**页面 `setData` 之前**注入（`injectAds(list)` 这种纯函数），不落 localStorage。
好消息：这意味着 `wx:for` 那段**不用拆**，只要在卡片块顶部加一个 `wx:if="{{p.isAd}}"` 分支。

### 3.3 首屏已经压到 765rpx，顶部不能再加东西

上一轮刚把首屏从 1080rpx 压到 765rpx（双卡合并 + 最近搜索收起），多露出半条帖子。
→ **列表顶部 banner 不要做**（§2 里也列为第二梯队）。这条约束是上一轮优化的直接后果，写在这里防止将来有人顺手加回去。

## 4. 收益量级（按公开 eCPM 参考值估算，非承诺）

| 形式 | 参考 eCPM | 假设 DAU 500、人均 2 次曝光 |
|---|---|---|
| banner | 5–30 元 | 约 **10 元/天 ≈ 300 元/月** |
| 插屏 | 15–40 元 | 频次受限，约 100–300 元/月 |
| 激励视频 | 50–120 元 | 取决于是否有可换的东西，按 §2-6 约 200–600 元/月 |
| 自营商家（5 个位） | 200–500 元/位/月 | **1000–2500 元/月** |

结论：**官方广告在当前体量下只能覆盖服务器成本**。真要覆盖运营，
得靠自营商家 + 「闲置」板块的撮合价值，不是靠 banner。

---

## 5. 合规红线（校园 + 学生用户，比一般小程序严）

1. **必须标注「广告」**，不能伪装成普通帖子或系统提示；工商登记的是「互联网广告」，这属于硬要求。
2. **禁投**：校园贷 / 网贷、医美、医疗、金融理财、彩票、游戏充值、学科类培训（双减后本身违法）。
   校园周边商家优先：打印店、驾校、租房、考研/考证机构（需查营业执照与办学许可）。
3. **不得诱导**：不能「点广告解锁评论」「点广告才能发帖」，激励视频只能换非核心权益（加曝光、盲盒次数）。
4. **隐私政策要改**：明确写「本小程序含广告，广告相关数据由广告平台处理」。现有 `docs/PRIVACY-CHECKLIST.md` 需同步。
5. **主体与类目**：论坛/社区类目对个人主体限制较多。接广告前先确认小程序主体与所选类目匹配，
   否则可能连广告位审核都过不了 —— 这一步在 mp 后台就能看，比改代码重要。

---

## 6. 什么时候开始做

前置条件（按顺序，缺一不可）：

1. 小程序已正式发布、连续运行 2 周无审核下架
2. 累计 UV 达标（后台「流量主」页会直接告诉你差多少）
3. 有内容审核机制 —— **已有**（云端 `mediaCheckAsync` + 举报 + 申诉），这项不用额外准备

满足后，落地成本：

| 要做的事 | 工作量 | 备注 |
|---|---|---|
| 建 `components/ui/ad-slot/`（读 `app_config` 开关，默认关） | 半天 | 开关在云端改，不用重新发版 |
| 详情页内容流末尾挂一个 | 半天 | 约束见 §3.1 |
| 列表第 5 条后注入 + 卡片分支 | 半天 | 约束见 §3.2 |
| 曝光 / 点击埋点（没有这个没法跟商家报价） | 1 天 | 复用现有 `utils/report.js` 通道 |

**现在不需要做的**：不用留空白占位块（空着比没有更难看，也会让首屏变回 1000rpx 以上），
不用提前申请广告位 ID（申请了长期不用会被回收）。

---

## 7. 一句话结论

代码层面**不需要现在预留**，位置层面**需要现在定死**：
顶部不加、详情页底部不能 fixed、广告不落缓存。
这三条已经写进本文档，将来接广告是「半天组件 + 半天接线」，不会返工。
